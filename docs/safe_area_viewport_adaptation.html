💡 iPhone 18 单一安全壳执行法则

1. 底色全景穿透：
html, body { position: fixed; inset: 0; background: var(--c-bg); }
深色背景直接延伸到灵动岛、手机四角圆弧（R=54px）和底部手势横条背后，彻底告别浏览器黑边/白条。

2. 外层独占避让：
全站仅由最外层容器（.main-container）声明一次：
padding-top: env(safe-area-inset-top);
padding-bottom: env(safe-area-inset-bottom);

3. 业务组件零感知：
内部的 .agent-chat-composer 与 .workspace-tabs 完全不再编写任何 env()。输入框直接以标准 Flex 沉底，与底部的 Home Bar 天然贴合，底部的 50px 冗余空白彻底消失！

📖 Duo 竖屏：笔记本 / Console 姿态解密

为什么以前下半部分是大片空白？
因为双屏展开竖着握持时，纵向高度通常高达 1400px+。如果只把它当作单张网页渲染，内容都在上面，底部的输入框又因为双重 padding 悬在中间，导致下半块屏幕几乎全部被浪费。

最佳利用模式：上下双屏联动（Top-Bottom Dual View）
• 上半屏（视线直视）：固定呈现 Agent 对话思考流或代码编辑器；
• 下半屏（手持操作）：展开为完整的 Tmux 实时终端 + 大键位控制基座。

⚡ CSS Viewport Segments API 驱动

@media (vertical-viewport-segments: 2), (screen-spanning: single-fold-horizontal) { /* 上半屏自动对齐第一个视口段 */ .chat-view-container { height: env(viewport-segment-height 0 0); } /* 下半屏对齐第二个视口段，铰链处完全留白保护，不跨缝撕裂文字 */ .terminal-view-container { height: env(viewport-segment-height 0 1); } }

🔬 为什么之前输入框下方会多出一道“输入框大小”的 50px 空白？

经过我们之前的排查，这个 50px 的空隙是由两组机制叠加产生的：

❌ 改造前：双重 Safe-Area + 100dvh 扣减陷阱
1. 安全区重复叠加：外层 .terminal-workspace 扣除了 34px (env-bottom)，内层 .agent-chat-composer 自身又扣了 34px (env-bottom)，两层相加产生了 68px 的物理抬高；

2. 100dvh 幽灵工具栏扣减：移动端浏览器内核误扣除了不存在的 44px 浏览器底部导航条，把 .main-container 顶格底边卡在了半空中；

3. 视觉表现：输入框漂浮在离屏幕底部约 50~60px 的半空中，底下露出一大截未利用的死区背景。
✔ 改造后：外层单一安全壳 + 内层纯净 Flex 贴底
1. 全景铺底：根节点 position: fixed; inset: 0;，消除任何白边黑边；

2. 单一安全壳：全站只有 .main-container 消费一次 env(safe-area-inset-bottom)，只避让一次真实的 Home 手势横条；

3. 内层组件零污染：输入框 padding-bottom: 0，紧紧吸附在安全壳的最底沿，这 50px 直接全部释放还给上方的内容聊天流！

🖥️ PC 桌面端为何能做到 100% 零影响？

1. PC 端环境变量天然为 0：在 PC 桌面（Windows/Mac Chrome/Firefox）上，env(safe-area-inset-*) 严格求值为 0px，因此安全壳在 PC 上等同于无任何额外 padding 的标准全屏容器；
2. 消灭移动端侵入代码：以前在子组件里写死的 max(8px, env(...)) 会在 PC 端无端垫高 8px，收拢到外层后，PC 端的子组件完全是原汁原味的 Desktop CSS；
3. MacBook 刘海屏全屏体验更佳：如果在带刘海的 MacBook Pro 全屏 Safari 运行，顶栏会自动由外壳避让刘海，完全无需专门编写 Mac 适配逻辑。
